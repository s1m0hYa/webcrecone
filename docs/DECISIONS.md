# 주요 설계 결정

각 항목은 선택 당시의 기록이다. 현재 동작은 뒤의 변경 결정을 함께 따른다.
robots 200 HTML 예외는 D016, 로컬 웹 서비스 철회는 D018, 단순 const·별칭 추적은 D019에 있다.
호출 진단·변수 목록·로컬 JS 입력·작은 문법 확장은 D020을 따른다.
응답 MIME에 따른 재귀 분석과 명시적 모듈/문서 참조 확장은 D021을 따른다.
URL/응답 수신 경계 보완과 base URL/출처 분리는 D022를 따른다.
미구현 개선 제안은 FUNCTIONAL_SPEC.md와 STATUS.md에서 관리하며 완료된 설계 결정과 구별한다.

## D001 — 루트 패키지와 표준 라이브러리

설치 없이 `python -m webrecon`으로 실행하기 위해 src 레이아웃/배포 의존성을 두지 않았다.
requests, 브라우저, Docker, 외부 API는 필요하지 않다. 명시적인 모듈 조합으로 유지한다.

## D002 — origin 단위 명시적 승인

스킴·정확한 호스트·포트 조합으로 범위를 표현한다. 호스트 문자열 접두사나 서브도메인 자동
포함은 승인 범위를 넓힐 수 있어 제외했다. 경로 단위 정책은 현재 지원하지 않으며 문서화했다.

## D003 — http.client의 연결 단계만 교체

urllib.request의 기본 리다이렉트, 프록시, 검증 뒤 DNS 재조회를 피하기 위해 http.client를 쓴다.
DNS 결과를 검사한 뒤 선택 주소에 직접 연결한다. 프로토콜 파싱은 표준 라이브러리에 맡긴다.
TLS 검증과 원래 호스트의 SNI는 유지한다. 단일 선택 IP 실패 때 다른 IP로 재시도하지 않는다.
별도 HTTP 파서나 라이브러리 도입보다 작고 검토 가능한 구성을 우선했다.

## D004 — robots를 클라이언트 내부에서 강제

수집기마다 robots 검사를 넣으면 새 수집기가 빠뜨릴 수 있다. public fetch가 자동으로
origin별 정책을 읽고 적용한다. 정책 자체를 읽는 예외는 private 함수에만 있다.
robots 접근 실패 시 중단하되, 2026-11-15 사용자 요청으로 404/410은 부재로 기록하고 계속한다.
이후 명시적 continue의 제한적 200 HTML 예외를 추가했다(D016).
stdlib 해석의 wildcard/Allow 차이는 모든
Disallow를 보수적으로 합치는 방식으로 보완했다. 과잉 차단 가능성을 정확성보다 우선했다.

## D005 — 정적 참조와 자동 탐색 분리

a/area 링크만 페이지 BFS 후보가 된다. 폼, API, 쿼리, 스타일, iframe, sitemap 목록은
발견만 기록한다. 2026-11-15 사용자 요청으로 승인 범위의 HTML script src .js/.mjs는
남은 요청 예산으로 읽어 정적으로 분석한다. JS에서 발견한 URL은 다시 방문하지 않는다.
폼 자동 제출이나 임의 API 호출을 기능 확장에 포함하지 않는다.
첫 origin의 선택적 /sitemap.xml 외에는 robots에 나열된 임의 sitemap도 자동 호출하지 않는다.

## D006 — 손실을 허용하는 결과 형식

비밀 값 유출을 줄이기 위해 입력값·쿠키·본문·대부분의 헤더 값을 제거한다.
원본 HTML 기반 재분석 대신 이미 추출한 JSON 구조를 재분석한다. 원본 복원, 세션 재현,
쿼리 값별 엔드포인트 구분은 제공하지 않는다. 분류는 후보와 근거만 남긴다.

## D007 — 동기 제한기와 테스트 시계

monotonic 완료 시각을 기준으로 최소 간격을 보장한다. 시작 간격만 재면 긴 요청 후 대기 없이
다음 요청이 나갈 수 있으므로 사용하지 않았다. 실제 HTTP에는 스레드/병렬 처리를 쓰지 않는다.
clock/sleep 주입은 테스트 지연을 없애기 위한 코드 인터페이스이고 CLI에는 노출하지 않는다.

## D008 — 제한된 환경에서 검증 상태를 구분

현재 환경은 `python` 명령이 없고 python3 3.12.3을 제공한다. 전역 별칭이나 설치를 추가하지 않는다.
루프백 소켓 생성도 권한 거부되어 승인 우회 없이 실제 서버 테스트를 skip 처리했다.
대신 명시적인 메모리 소켓으로 동일한 표준 HTTP 전송/응답 파싱 경로를 검증한다.
이는 실제 서버 성공을 대신하는 증거가 아니므로 MVP의 실제 HTTP 검증 조건은 남아 있다.

## D009 — robots 경로 관찰과 URL/API 목록

2026-11-15 사용자 요청으로 robots 선언을 별도 robots_paths에 남긴다. 패턴을 확장하거나
선언만으로 방문하지 않는다. 구체적인 접두 경로는 존재 미확인 후보로 엔드포인트에 병합한다.
출처·줄 번호·종류를 보존하고 같은 값의 선언을 중복 제거한다. 민감 값 제거 후 중복 제거하므로
마스킹된 항목은 합쳐질 수 있다. 정책 파일별 출력 수 제한은 접근 제어 규칙에 영향을 주지 않는다.

url_list/api_list는 기존 관찰에서 파생한다. domain 그룹은 호스트 이름, path 그룹은 정확한
경로로 묶고 스킴/포트는 각 origin에 보존한다. 실제 응답 관찰 메서드와 폼/JS 선언을 분리하여
POST 선언이 실제 POST 요청처럼 보이지 않게 한다. 기존 schema v1의 GET 전용 기록도 재분석한다.

## D010 — robots 부재 허용과 제한적인 JS 분석

초기 요구사항의 robots 실패 시 중단 원칙은 이후 사용자의 명시적인 변경 요청에 따라
404/410 부재 응답에 한해 완화했다. 이후 200 HTML 예외는 D016에서 별도로 추가했다.
접근 거부·전송 실패·잘못된 정책에는 그대로 중단한다.
도입 당시 JS 지원은 stdlib 정규식 기반 리터럴 관찰로 제한했다(현재의 상수 추적은 D019 참조).
AST 엔진, 브라우저, 코드 실행,
API 검증 요청을 추가하지 않는다. read_scripts=false로 외부 JS 읽기를 끌 수 있다.
정적 분석의 메서드도 선언 단서이며 런타임 값이나 실제 지원 메서드를 확정하지 않는다.

## D011 — 동적 주소를 구체적인 URL과 분리

2026-11-15 사용자 요청의 문자열 결합·템플릿 URL을 작은 문법으로 관찰한다.
fetch/axios에서 문자열·변수/속성 이름의 결합을 찾고 변수 값을 자리표시자로 남긴다.
당시에는 JS 해석기나 상수 전파를 도입하지 않았다(D019에서 단순 const 추적 추가).
미확인 base의 도메인을 추측하지 않고 별도의
endpoint_patterns로 보존한다. 보고서의 patterns 목록도 domain/path로 묶을 수 있다.

## D012 — 여러 알려진 페이지를 시작점으로 사용

사용자 제공 링크는 JSON seed_urls 또는 --seeds-file로 받는다. target_url을 첫 시작점으로
유지하고 추가 목록을 합쳐 정규화·중복 제거한 뒤 모두 깊이 0으로 등록한다. 파일은 UTF-8
한 줄 한 URL로 제한해 설치나 별도 형식을 요구하지 않는다. URL로 승인 범위를 추론하지 않으며
범위 밖 입력은 네트워크 전에 거부한다. 위험 경로·쿼리·API는 기존 정책대로 기록만 한다.
하나의 동기 클라이언트와 예산을 공유하므로 시작점마다 요청 상한이 늘어나지 않는다.
최대 50개 시작점, 입력 1,000항목·1MiB 제한을 두고 plan에서도 목록을 검사할 수 있게 했다.

## D013 — HTTP User-Agent와 robots 식별자 분리

2026-11-15 사용자 요청의 Chrome/158.0.0.0 문자열을 config.py의 HTTP_USER_AGENT로 관리하고
공통 전송 경로에 적용한다. robots 평가 식별자는 기존 WebRecon/0.1로 유지해 헤더 변경이
기존 도구 전용 Request-rate 등의 제한을 없애지 않도록 했다. 실제 브라우저를 실행하거나
robots의 200 HTML 응답을 부재로 간주하는 변경은 포함하지 않는다.

## D014 — robots 실패 진단과 관찰 상태 재구성

2026-11-15 사용자 실행 결과의 200 HTML 응답과 입력 주소 집계 혼동을 해결하기 위해
robots_checks와 방문 상태·근거별 집계를 추가했다. diagnostics.py는 전송과 오프라인 보고서에서
같은 메타데이터 진단을 사용하기 위한 작은 순수 모듈이다. 본문은 구조적 특징의 불리언만 남긴다.
HTML 응답을 무조건 robots 부재로 허용하는 대안은 접근 안내를 오인할 수 있어 채택하지 않았다.

기존 JSON에도 적용하기 위해 analyzer가 저장된 요청으로 방문 상태를 재구성한다. 전체 후보는
유지하면서 입력만 존재하는 후보, 콘텐츠에서 발견한 경로, 응답을 받은 경로를 독립 집계한다.
응답 수신과 성공적인 HTML 파싱을 분리하고, 큐 등록 상태는 initial_disposition으로 보존한다.
기존 schema_version=1을 유지하며 파생 필드를 추가한다. 초기 큐 후보의 disposition은 최종 상태로
바뀌므로 이를 사용하는 소비자는 initial_disposition 또는 visit_status를 확인해야 한다.
과거 robots 기록에서는 본문 유효성을 추정하지 않고 metadata 기반 진단과 unknown을 구별한다.

## D015 — 이미 받은 robots HTML을 별도로 파싱

2026-11-16 사용자의 "응답 온 것에서 URL을 파싱" 요청에 따라, 정책 확인 실패 때문에
이미 받은 HTML까지 버리던 흐름을 수정했다. 클라이언트는 제한된 수신 응답을 일시적으로
넘기고 크롤러가 기존 파서를 적용한다. 파싱 자료는 response_documents에 별도로 저장한다.
이 문서의 링크·폼·인라인 JS와 동적 패턴을 기존 URL/API 목록·오프라인 보고서에 통합한다.

추가 네트워크 없이 이미 받은 정보의 활용도를 높이는 변경이다. robots 접근 실패를 허용으로
바꾸거나 응답의 링크·스크립트를 자동 방문하는 방식은 포함하지 않았다. 실제 seed 페이지와
응답 문서를 구분해 수집 성공을 과장하지 않으며, 기존 결과에 미저장한 본문은 복원하지 않는다.

## D016 — 명시적 200 HTML 예외로 seed 탐색 계속

2026-11-16 사용자가 HTML URL 추출 후에도 재귀 탐색이 중단되는 문제를 지적하고 탐색 진행을
요청했다. 기존 D015는 수신 본문만 분석했으므로 이를 충족하지 못했다. robots_html_policy=continue를
추가했다. 설정을 생략하면 기본값은 stop이다.

200·HTML MIME·HTML 형태·완전한 수신·정책 지시문 없음이라는 조건에서만 예외를 허용한다.
부재나 유효 정책으로 오인하지 않도록 continued_unverified 및 정책 미확인 사유를 저장한다.
임시 정책은 origin별로 캐시하며 기존 BFS가 seed와 링크를 탐색하고 페이지 참조 JS를 읽는다.
모든 robots 오류를 무시하는 옵션은 만들지 않았다. 정상 Disallow, 접근 거부, 부하 신호,
범위·주소·간격·예산·메서드 제한을 유지한다. 실제 robots 제한 준수 여부는 이 모드에서 미확인이다.

## D017 — JSON에서 생성하는 단일 오프라인 HTML

2026-11-16 사용자가 endpoint 종류·결과와 파일 위치를 보기 좋게 요청했다. 수집기를 확장하지
않고 JSON 관찰 자료를 HTML 표로 표현한다. scan은 JSON 뒤에 HTML을 저장하며 기존 결과는
report --format html로 재생성한다. 응답/선언 메서드, HTTP 응답/미방문, 파일 참조/파일 존재를
구분한다. 도메인·분류·메서드·방문/범위 필터와 경로·출처 검색은 브라우저 로컬 DOM만 사용한다.

외부 템플릿 엔진·차트 라이브러리·CDN·웹 서버 대신 표준 라이브러리와 고정 HTML 템플릿을 선택했다.
설치 없는 실행과 오프라인 열람을 유지하고 target 링크/이미지를 활성화하지 않는다. 이스케이프와
스크립트 해시 CSP를 함께 적용한다. 원본 JSON 보존과 기존 출력 경계/원자적 저장을 재사용한다.
이번 구현은 단일 실행의 정적 보고서다. 이력 관리·서버 대시보드·대용량 표 가상화는 도입하지 않았다.

## D018 — 로컬 웹 작업공간 도입 철회

2026-11-18 사용자의 롤백 요청으로 직전에 추가했던 serve 명령, 로컬 서버·작업공간·웹 UI와
관련 테스트를 제거했다. CLI 정찰, URL/API/패턴 분석, JSON 및 오프라인 HTML 보고서는 유지한다.
사용자 config/seed/기존 output 자료는 삭제하거나 수정하지 않는다. 표준 라이브러리 의존성 정책도 유지한다.

## D019 — 같은 스크립트의 단순 const와 별칭 추적

2026-11-18 사용자가 동적 변수 처리 개선에 동의하여 `fetch(url)`의 단순 const 선언 연결을
추적하도록 확장했다. 정규식만으로는 주석/문자열과 선언 범위를 구분하기 어려워 작은 토큰화·범위
분석 모듈을 추가했다. 문자열·별칭·결합·단순 템플릿만 조합하며 외부 AST 라이브러리나 JS 실행기는
도입하지 않았다. 표준 라이브러리만으로 설치 없는 실행을 유지한다.

함수/블록/화살표 함수/for 범위를 분리하고 가까운 선언을 사용한다. let/var, 함수 인자, 재할당,
선언 순서·충돌·순환, 함수/객체/산술 표현식은 추측하지 않고 이유를 기록한다. 파일 간 import나
인라인 script 간 값 전달은 다루지 않는다. 전체 JS 문법을 재현하지 않으므로 누락 가능성을 문서화했다.
이유 기록은 후보로 남길 수 있는 패턴에 한정된다. 직접 미지원 인자를 비롯한 모든 제외 호출의
사유를 집계하는 기능은 구현하지 않았다.
깊이·해석 횟수·토큰·조합 크기를 제한해 순환 및 지수적인 별칭 확장을 차단한다.

URL 참조와 추적 기록을 한 번의 parse_script와 같은 추출 예산으로 만든다. 완성된 문자열 주소는
URL/API 후보에도 넣고 미완성 패턴은 분리한다. 모두 기록 전용이며 크롤링/실제 메서드 관찰과 구별한다.
JSON/HTML에는 마스킹된 주소, 이름·위치·해석 상태·미확인 이유만 남기며 원문 코드·상수 값 목록은
저장하지 않는다. 민감한 이름의 초기화 값은 추적 대상에서 제외한다. 과거 JSON의 원본 JS는 복원하지 않는다.

## D020 — 제한된 호출 진단과 오프라인 JS 분석

2026-11-19 사용자가 남은 네 가지 개선 작업을 요청해 검출/해석/제외 진단, 변수 목록과 HTML 필터,
analyze-js CLI, 이스케이프 문자열·단순 괄호 식 지원을 추가했다. 전체 AST 엔진·브라우저·외부 패키지는
도입하지 않았다. 호출 진단은 지원 형태에 한정되며 토큰화 중단이나 미지원 문법의 미검출 수는 모른다.
호출 식/인자를 보존하는 대신 고정 이유 코드·위치·메서드·집계를 남긴다. 상세와 진단 단위도 예산으로
제한하고 생략 수를 알린다. 기존 parse_script 반환 형식과 JSON schema_version=1은 유지한다.

변수는 주소 패턴의 선언/미확인 근거에서 파생한다. 출처·인라인 순번·선언/범위 위치를 식별 기준으로
삼아 다른 함수의 같은 매개변수 이름을 합치지 않는다. 전체 심볼 색인이나 원본 상수 값 저장은 하지 않는다.
HTML에는 해석 상태/출처 필터와 진단 상세를 추가하고 기존 고정 UI·이스케이프·CSP를 재사용한다.

analyze-js는 로컬 일반 파일 하나만 읽는다. UTF-8/BOM·1MiB·기존 추출 상한을 적용하고 FIFO/장치는
거부한다. base URL은 문서 상대 주소 기준이며 승인/존재를 확인하지 않는다. 네트워크 클라이언트를
생성하지 않고 outside_scope=null로 표시한다. 원본 경로·파일명·코드는 결과에 저장하지 않는다.
문자열 escape는 허용 목록 디코더, 괄호는 제한된 기존 식의 재귀 처리로 구현했다. eval·함수/산술
실행으로 정확도를 높이는 대안은 배제했다. 미지원 함수/동적 호스트도 진단에 제외 이유를 남긴다.

소켓 제한·브라우저 미설치로 실제 TCP와 화면 검증은 별도 과제로 남긴다. 단위/메모리 전송 및
고정 UI의 DOM 모의 검증을 실제 서버·브라우저 성공으로 간주하지 않는다. 로컬 웹 서비스는 재도입하지 않았다.

## D021 — 받은 응답을 다시 분석하는 제한적 재귀 탐색

2026-11-19 사용자가 발견한 엔드포인트의 HTML/JS 응답에서도 새 URL을 추출해 탐색을 이어가도록
요청했다. 이전의 페이지 처리 후 JS 일괄 처리에서는 새 문서가 생겨도 돌아가지 않았고 예상 MIME과
다른 응답을 버렸다. 문서 BFS와 JS 큐를 한 run 루프에서 처리하고 _analyze_response에서 실제 MIME을
기준으로 파싱하도록 변경했다. 별도 비동기 작업 시스템이나 네트워크 경로는 도입하지 않았다.

명시적인 a/area href·iframe.src·location 이동과 script/import/export-from 참조만 새 요청 후보로
삼는다. fetch/XHR/폼 및 일반 URL 문자열을 무조건 GET하는 방식은 원래의 기능 실행 금지 정책과
맞지 않아 채택하지 않았다. bare/dynamic import나 파일 간 변수 전달을 추측하지 않는다.
기존 Script 토큰을 재사용하는 js_references.py로 참조 근거를 추출하고 API 후보와 종류를 구분한다.
import 상대 경로는 최종 JS 파일 URL을, fetch/location은 처음 발견 문서 URL을 기준으로 삼는다.

직접 JS 참조를 문서 깊이와 별개로 읽던 동작은 유지하고, 신규 max_script_depth(기본/상한 2)를 둔다.
JS→HTML→JS나 JS→페이지→JS 경로에서도 JS 깊이를 초기화하지 않는다. 모든 경로가 같은 요청/큐
예산·중복 방지·범위·robots·완료 후 간격을 공유하며 자동 재시도는 없다.

페이지 요청이 JS이면 pages에는 응답 관찰, scripts에는 분석 구조를 남긴다. JS 요청이 HTML이면
response_documents(purpose=script)에 남겨 페이지 시도 횟수를 왜곡하지 않는다. 오류 HTML/JS는
이미 받은 본문에서 후보만 추출하고 추가 요청을 차단한다. 오류 HTML은 정상 pages_parsed에 합치지
않는다. JSON 스키마 버전은 유지하고 선택 필드를 추가한다. 이전 원문 없는 결과에 새 후보는 복원할 수 없다.

## D022 — URL 조합과 응답 완료의 명시적 검증

전체 검토에서 빈 쿼리 구분자·제어 문자 손실, Content-Length 미달 응답 파싱,
비정상 Retry-After의 중단 누락을 재현했다. 표준 파서 사용만으로 이 정책 경계가 보장되지 않았다.
scope.resolve_reference가 URL 조합 전 검사를 맡고, 전송 클라이언트가 본문 길이 미달과
제한 신호를 책임진다. 새로운 전송 계층이나 외부 패키지는 추가하지 않는다.

HTML base를 외부 JS에도 전달하되 source/document의 실제 출처를 해석 기준 주소로 바꾸지 않는다.
base_url 선택 필드를 추가하고 기존 JSON은 저장된 정보만으로 재분석한다.
API 분류는 표시용 출처 20개 제한과 분리해 저장된 파서 참조도 확인한다.
수정 근거와 회귀 결과는 [전체 검토 기록](REVIEW.md)에 기록한다.

## D023 — 오프라인 보고서의 탭·분할 표시와 고정 자산 분리

전체 검토 2차에서 긴 목록의 화면 부담을 줄이기 위해 8개 탭과 표별 50/100/250행 분할을 추가했다.
데이터는 계속 JSON/HTML에 포함하고 검색은 전체 표를 대상으로 한다. 서버·외부 라이브러리·
가상화 프레임워크를 추가하지 않았으며 DOM 메모리 비용은 남는다. JS 비활성 시 전체 표를 읽을 수 있다.
키보드 탭 이동, 빈 결과, 필터 변경 후 페이지 초기화, 인쇄의 검색 결과 전체 표시를 함께 구현했다.

유지보수를 위해 UI 코드와 스타일을 report_ui.js/report_style.css로 분리하되 출력 시 HTML에 내장한다.
출력 파일을 다른 컴퓨터로 옮길 때 자산 경로가 깨지지 않으며 고정 스크립트 CSP 해시도 유지한다.
소스 패키지 복사 실행은 세 자산을 포함해 Python -S로 확인한다. Node DOM 검사는 선택적 개발 검증일 뿐
Python 제품/필수 unittest의 의존성이 아니다. 관계 트리·원문 코드 뷰어·함수 호출 추적은 추가하지 않았다.

## D024 — 저장된 출처와 로컬 파일을 이용한 페이지 탐색

실제 HTML 생성 경로에 페이지·JS·함수·API 관계 탐색기를 포함한다. 사이트 구조를 다시 추측하는 대신
참조한 파일과 구문 위치를 연결한다. 문자열/경로 단서와 호출 선언을 따로 표시한다. 이름 있는 함수
선언과 같은 파일의 직접 호출만 기록하며 수집 큐에는 영향을 주지 않는다.

소스 뷰어의 기본 입력은 정적 관찰 근거다. 실제 소스는 사용자가 선택한 로컬 파일을 일시적으로 읽고
새 결과의 바이트 지문과 대조한다. 보고서 크기와 민감정보 보존 문제 때문에 본문을 HTML에 포함하지 않는다.
원본 웹 주소는 수집 시 원래 주소와 저장 주소의 동일성을 확인한 경우에만 수동 열기를 검토한다.

## D025 — 원본 열기와 함수·변수 관계 탐색

사용자가 원본을 따로 여는 작업 흐름을 선택해 HTML의 내장 코드 뷰어와 전용 파일 지문을 제거했다.
상세 패널 공간을 같은 스크립트의 직접 호출·역방향 호출자·변수 사용 위치에 쓴다. 의존성 설치와
런타임 계측 없이 기존 토큰과 선언 범위를 재사용한다. 파일 간 모듈 연결과 동적 디스패치는 미지원이다.
