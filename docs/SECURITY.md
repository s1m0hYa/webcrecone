# 안전 정책과 알려진 한계

## 승인과 범위

대상, 허용 origin 목록, --ack-authorized가 모두 있어야 네트워크를 시작한다.
plan/dry-run/report는 DNS나 소켓을 사용하지 않는다. 승인 플래그는 사용자의 확인일 뿐
법적 권한을 기술적으로 증명하지 않는다. origin 내 모든 경로에 대한 사전 승인을 전제로 한다.

사용자가 제공한 시작 URL 목록도 승인 범위를 늘리지 않는다. 모든 입력의 형식·origin을
네트워크 전에 검사하며 범위 밖 주소가 있으면 설정을 거부한다. 추가 seed의 쿼리/API/상태 변경
의심 URL은 발견만 기록한다. 필수 target_url의 이런 경로는 설정 단계에서 거부한다.
여러 시작점이 하나의 클라이언트·간격·전체 요청 예산·robots 캐시를 공유한다.
시작 파일은 최대 1MiB만 읽고 원본 파일명/내용을 결과나 오류에 복사하지 않는다.
결과의 seed_urls/start_urls도 공통 마스킹을 적용한다.

HTTP/HTTPS만 허용하고 userinfo, 제어 문자, 역슬래시, 비정상 포트/호스트/escape를 거부한다.
fragment를 버리고 호스트·기본 포트·unreserved escape를 정규화한다. 접두사 비교가 아니라
정확한 (scheme, host, port)을 비교한다. 다른 서브도메인과 포트도 별도 승인 대상이다.
모든 리다이렉트에 같은 검증을 적용한다. robots 리다이렉트는 동일 origin으로 더 제한한다.
링크/JS/리다이렉트를 조합하기 전 제어 문자를 검사한다. urljoin의 문자 제거에 의존하지 않는다.
빈 `?`도 정규화와 표시에서 보존하여 seed·HTML·JS·리다이렉트 모두 쿼리 방문 차단을 적용한다.

## DNS와 연결

매 연결 전에 getaddrinfo 결과의 모든 주소를 검사하며 하나라도 금지 주소면 전부 거부한다.
선택한 IP의 sockaddr로 직접 socket.connect하여 전송 라이브러리의 재조회와 재시도를 제거한다.
HTTPS는 `ssl.create_default_context()`를 사용하고 원래 호스트로 인증서·SNI를 검증한다.
검증을 끄는 옵션은 없고 시스템 프록시·쿠키 저장소·.netrc·인증 헤더를 사용하지 않는다.

ipaddress의 비전역/사설/루프백/링크로컬/멀티캐스트/예약 주소를 차단한다.
IPv4-mapped IPv6, 6to4, Teredo, NAT64 well-known prefix 등은 보수적으로 차단한다.
Python 버전별 특수 주소 분류 차이를 줄이기 위해 IPv4 192.0.0.0/24,
IPv6 2001::/23 및 3fff::/20 등도 차단하고 IPv6는 2000::/3 내로 제한한다.
루프백 예외는 숫자형 IP를 origin과 allowed_loopback_hosts 양쪽에 지정해야 한다.
localhost 이름, 사설망 전체, CIDR 예외는 지원하지 않는다.

IP 고정은 DNS 검증·연결 사이의 주소 변경을 줄이지만 OS 라우팅, VPN, NAT, 투명 프록시,
운영체제 resolver/hosts 설정, 시스템 신뢰 저장소까지 보증하지 않는다.
표준 getaddrinfo는 동기 OS 호출이므로 10초 timeout으로 실행 시간을 강제 제한할 수 없다.
별도 스레드·프로세스·외부 resolver 없이 이 부분의 엄격한 deadline은 제공하지 않는다.

## 요청 제한

하나의 동기 클라이언트만 사용한다. 재진입/동시 호출은 잠금으로 거부한다.
완료 시점 monotonic을 기록하고 이후 요청 전 남은 간격을 모두 기다린다.
성공, HTTP 오류, DNS/전송 실패, robots, sitemap, redirect 모두 동일 경로를 사용한다.
네트워크 시도 100회, 페이지 후보 50개, 문서 이동 깊이 2, JS 참조 깊이 2, redirect 3회 이하가 상한이다.
직접 참조 JS는 JS 깊이 0이고 후속 모듈부터 증가한다. 문서/JS 전환으로 깊이·예산을 초기화하지 않는다.

소켓 timeout은 최대 10초다. 본문 read 사이에는 전체 경과시간도 확인하지만
DNS 및 표준 라이브러리의 헤더/청크 프레이밍 내부 읽기까지 정확한 벽시계 10초를
보장하지는 않는다. 아주 느린 헤더/청크 전송에서 초과할 수 있다.
본문 최대 보관 크기는 1MiB, 초과 감지에 1바이트를 더 읽는다. 읽기를 끝내면 응답과 소켓을
명시적으로 닫는다. 압축은 요청하지 않고 압축 응답을 해제/분석하지 않는다.
Content-Length를 채우기 전에 EOF가 오면 incomplete_response_body로 기록하고 부분 본문을 버린다.
부분 robots로 접근 허용을 판단하지 않는다. 길이/청크 종료 표시가 없는 응답은 EOF가 끝이므로
서버가 의도한 전체 문서인지 추가로 판별할 수 없다.

429/503 또는 어떤 상태에서든 Retry-After가 있으면 추가 요청을 영구 차단한다.
표현 가능한 Retry-After 초/날짜는 남은 초로 기록하되 재시도는 하지 않는다.
중단 결정은 값 해석보다 먼저 수행하며, ASCII 정수가 아닌 숫자 모양 문자도 예외로 중단을 취소하지 않는다.
자동 재시도, DNS 후보 순회, 인증 챌린지 재요청, 프록시 재시도는 없다.

## robots와 GET 부작용

HTTP User-Agent는 config.py의 사용자 지정 HTTP_USER_AGENT를 모든 요청에 공통 적용한다.
robots 평가 식별자는 WebRecon/0.1로 분리해 헤더 변경으로 기존 도구 전용 Disallow,
Crawl-delay, Request-rate 적용이 사라지지 않도록 한다. 브라우저 실행이나 인증 상태를 재현하지 않는다.

robots 200의 비압축 text/plain(또는 타입 미지정)만 정책으로 처리한다.
사용자 요청에 따라 404/410은 명시적 부재로 기록하고 HTML/JS 수집을 계속한다.
401/403 등 접근 거부, 통신/서버 오류, 잘림, 명백한 잘못된 내용이면 전체 실행을 중단한다.
HTML 응답은 기본 중단하며 아래 명시적인 continue 설정에만 제한적 예외를 적용한다.
빈 robots는 허용 정책으로 해석한다. stdlib RobotFileParser에 더해 모든 agent 그룹의
Disallow를 적용하며 `*`, `$`를 처리한다. Allow 예외를 보수적으로 무시하므로 과도하게
차단할 수 있다. 정수/소수 Crawl-delay를 반영하고 Request-rate를 최소 간격으로 환산한다.
60초보다 긴 간격이나 잘못된 delay 선언은 기다리는 대신 중단한다. 완전한 RFC 파서는 아니다.

robots 검사 실패는 MIME 불일치, 접근 거부, HTTP 상태, 전송 실패, 잘림, HTML 본문 등으로
구분한다. 진단에는 본문을 저장하지 않고 HTML 형태/User-agent 지시문/빈 내용 여부만 남긴다.
이는 휴리스틱 신호이며 접근 안내·로그인·SPA 여부를 판정하거나 정책을 무시하는 근거로 쓰지 않는다.
기본 모드에서 200 HTML 및 MIME이 잘못된 정책은 중단한다. 과거 결과의 미기록 본문 특징은 복원하지 않는다.
일반 텍스트 마스킹은 유지하고, 도구가 정의한 오류 코드만 터미널에서 정확한 이름으로 표시한다.

이미 받은 robots HTML은 정책 허용과 독립적으로 정적 파싱한다. 링크·폼·인라인 JS 후보와
마스킹된 구조만 response_documents에 보존하며 원문을 저장하지 않는다. 401/403 HTML의
안내 링크도 발견할 수 있지만 접근권한이나 해당 경로의 존재를 검증한 결과가 아니다.
여기서 찾은 링크·외부 JS·API는 큐에 넣지 않고 추가 요청을 만들지 않는다. 잘림·압축·전송 실패는
분석하지 않으며 429/503/Retry-After 응답은 기존대로 본문 수집 전에 중단한다.

2026-11-16 사용자 요청으로 robots_html_policy=continue 예외를 추가했다. 완전히 수신된 200,
HTML MIME 및 HTML 형태, 오류·NUL·robots 지시문 형태가 없는 경우에만 seed 탐색을 계속한다.
robots의 실제 부재·접근 허용 여부를 확인한 것으로 취급하지 않고 continued_unverified로 기록한다.
HTML이 애플리케이션 기본 페이지인지 안내 페이지인지 확정할 수 없으므로 이 예외에서는
알 수 없는 robots 제한을 준수했다고 보장할 수 없다. 기본값은 stop이다. 정상 정책의 Disallow,
새 origin 검사, 접근 거부·전송 실패·부하 신호 중단 및 다른 네트워크 안전 제한은 유지한다.

쿼리 URL은 값에 관계없이 방문하지 않는다. 로그아웃·삭제·초기화·실행·편집·업로드 등의
의심 이름과 API 경로, 세미콜론 경로 파라미터도 차단한다. 반복 URL 디코딩으로 흔한 인코딩을
검사한다. 이는 휴리스틱이며 `/a` 같은 이름의 상태 변경 GET을 알아낼 수 없다.
폼은 제출하지 않고 자바스크립트, meta refresh, iframe, 외부 리소스를 브라우저에서 실행하지 않는다.
명시적 iframe.src 문서는 일반 페이지와 같은 범위·robots·깊이 제한을 거쳐 순차 GET할 수 있다.

robots의 Allow/Disallow는 별도 관찰 목록에도 저장한다. 빈 규칙은 제외하고 wildcard 패턴을
실제 URL로 확장하지 않는다. 일반 접두 경로는 존재 미확인 URL 후보로만 병합한다.
선언 관찰 수는 정책 파일당 max_items_per_page 이하이고, 이 제한으로 실제 접근 차단 규칙을
자르지는 않는다. 민감한 쿼리 값·경로 토큰은 공통 마스킹을 통과한다.

HTML script src와 JS import/export-from/단일 문자열 import()의 .js/.mjs 또는 확장자 없는 경로는
명시적 승인 범위와 robots 정책을 통과하면 순차 GET으로 읽을 수 있다. 문서 링크의 .js/.mjs도
JS 큐로 처리한다. 공통 요청 예산·간격·응답 크기·리다이렉트 제한을 적용한다.
받은 HTML/JS는 실제 MIME에 따라 분석한다. JS URL의 HTML도 분석하고 명시적 참조를 이어 탐색한다.
미지원 MIME·압축·잘린 응답은 분석하지 않는다. 200 이외 응답의 후보는 기록만 하고 큐에 넣지 않는다.
이 변경은 robots/sitemap의 접근 정책을 바꾸지 않는다. 부하 신호 이후에는 새 요청을 만들지 않는다.
인라인/외부 JS는 제한된 토큰화와 단순 const 문자열/별칭 추적으로 URL·메서드 단서를 찾는다.
주석·문자열 안의 호출 코드는 제외하며 JS 실행·eval/exec·함수 호출·브라우저 자동화를 하지 않는다.
완전한 문법 분석기가 아니므로 오탐/누락은 가능하다. 정규식/나눗셈이 모호하면 구간을 건너뛴다.
발견한 API 호출·일반 문자열은 요청하지 않으며 POST 등은 선언만 기록한다. 명시적인 location
계열 이동만 문서 큐 후보로 인정한다. 지역 이름이 관찰되면 브라우저 location 객체로 추정하지 않는다.
원본 JS, 요청 body, 헤더/인증값을 저장하지 않는다. fetch/location은 처음 발견한 문서의 base URL 기준,
import는 리다이렉트 후 최종 JS 파일 기준으로 상대 URL을 해석한다. bare specifier·import map·
동적으로 계산한 모듈 주소나 브라우저의 모든 해석 규칙은 재현하지 않는다.
base href가 외부 주소를 가리켜도 자동 요청의 승인 범위를 늘리지 않는다. 실제 문서 출처는 별도로 유지한다.

단순 const·결합/템플릿은 endpoint_patterns에 해석 상태·선언/호출 위치·미확인 이유를 남긴다.
함수/블록 등의 범위를 구분하고 let/var·재할당·선언 충돌·미지원 식은 값으로 확정하지 않는다.
토큰 수·깊이·해석 횟수·조합 크기에 상한을 둔다. 미확인 base를 현재 호스트로 가정하지 않는다.
함수 호출, 산술·객체 속성·파일 간 import·동적 호스트는 해석하지 않는다. token/password/secret 등
민감한 이름은 값을 따라가지 않고 해당 초기화식의 문자열도 일반 리터럴 후보에서 제외한다.
원문 표현식·상수 값 목록은 저장하지 않으며 URL의 쿼리 값과 알려진 민감 경로를 마스킹한다.
이름이나 경로만으로 모든 민감정보를 판별할 수는 없다. 문자열로 완성된 주소도 후보 기록만 하며
API 후보와 부분 패턴 어느 쪽도 추가 요청으로 연결하지 않는다. 모듈을 읽더라도 파일 간 값을 연결해 추측하지 않는다.

검출한 호출에는 해석/제외 수·이유·위치 진단을 남긴다. 원문 인자/표현식 대신 고정된 이유 코드만
사용한다. 토큰화 중단·모호 구간·미지원 문법에서 검출하지 못한 호출까지 센 것은 아니다.
상세와 스크립트 진단 수에도 상한을 두고 생략 수를 표시한다. 구버전의 미기록 정보를 복원하지 않는다.
parsed=true와 빈 후보 목록은 분석 완전성이나 공격표면 부재의 증거가 아니다.
변수 목록은 주소 패턴에 연결된 이름·범위·이유만 집계하며 전체 변수나 별도 값 목록을 저장하지 않는다.

허용된 문자열 이스케이프는 제한된 수동 디코더로 처리한다. 단순 괄호 식에도 기존 문자열 규칙과
별도 깊이 상한을 적용한다. 함수·산술·객체 접근을 실행하지 않는다. 복원된 주소도 같은 URL 마스킹을
통과하며 공백·제어 문자·역슬래시·비HTTP 주소는 후보에서 제외한다.

analyze-js는 사용자가 명시한 로컬 UTF-8/BOM 일반 파일 하나를 읽는다. 입력 크기는 최대 1MiB이고
파일 형식을 열기 전후 검사해 FIFO·장치·디렉터리를 거부한다. 원본은 수정하지 않으며 로컬 경로·파일명·
원문을 결과에 저장하지 않는다. base URL은 HTTP(S) 형식의 상대 주소 기준일 뿐 승인 범위가 아니다.
설정/클라이언트 생성·DNS·robots·HTTP 없이 분석하며 결과의 범위는 미평가, 응답 관찰은 없음이다.
출처 local:input.js는 표시용 식별자이며 요청하거나 열 수 있는 리소스 주소로 사용하지 않는다.
입력 파일을 허가된 범위에서 확보하는 것은 사용자의 책임이며 인증/자료 확보 기능을 추가하지 않는다.

sitemap XML은 크기를 제한하고 DOCTYPE/ENTITY/NUL을 거부한다. 외부 XML 리소스를 가져오지
않으며 urlset의 URL을 발견 자료로만 기록한다.

## 저장과 로그

모든 쿼리 값은 REDACTED로 바꾸고 파라미터 이름만 기록한다. URL fragment/userinfo,
폼 입력값·textarea/option 내용, 일반 메타 내용, 주석 내용과 본문 원문을 저장하지 않는다.
헤더는 이름을 기록하되 값은 기본적으로 제거한다. MIME·정수 Content-Length·간단한
Server/X-Powered-By 제품 이름/버전만 보존한다. Set-Cookie, 인증, Location 원문은 보존하지 않는다.
redirect 목적지는 URL 마스킹 경로로 따로 기록한다. 예외의 원문 문자열을 로그에 쓰지 않는다.

제목·이름·경로의 알려진 비밀 패턴·긴 토큰, 이메일 등을 보수적으로 치환한다.
하지만 임의의 제목, 짧은 경로 토큰, 헤더/필드 이름 안에 숨은 민감정보를 완전히 식별하지
못한다. 인증 없는 공개 데이터만 수집하며, 결과를 공유하기 전 사람이 검토해야 한다.
마스킹으로 서로 다른 경로가 합쳐질 수 있다. 수집 결과는 공개 가능한 데이터라는 보증이 아니다.

출력은 저장소 output 내부로 제한하고 경로 이탈과 symlink 이탈을 검사한다.
임시 파일 후 os.replace로 저장한다. 같은 사용자 권한을 가진 공격자의 파일시스템 동시 변경을
방어하는 경계는 아니다. 출력 파일과 로컬 설정은 Git 제외 대상이다.

## 검증의 한계

개발 자동 테스트에는 로컬 fixture와 모의 전송을 사용한다.
TLS의 주소 고정·호스트 검증 호출과 실패 처리는
mock으로 확인했으며 실제 TLS 서버와의 handshake는 검증하지 않았다.
개발 sandbox는 실제 루프백 소켓도 차단한다. 메모리 전송 테스트와 실제 서버 테스트를 분리하고
후자는 명시적으로 skip한다. 운영체제별 확인 상태는 STATUS.md를 따른다.

## 오프라인 HTML 출력

HTML 보고서는 마스킹된 관찰 구조만 표시하며 원본 HTML/JS/응답 헤더를 삽입하지 않는다.
URL은 다시 마스킹하고 모든 관찰 문자열은 HTML 문맥에서 이스케이프한다. 대상 URL은 텍스트로
표시하므로 보고서를 열거나 필터를 조작해도 대상 요청이 발생하지 않는다. 고정 UI 스크립트만
SHA-256 CSP 해시로 허용하고 connect/img/object/form-action/base-uri를 차단한다. 외부 자산은 없다.
원본 새 창 버튼은 사용자의 브라우저에서 독립적인 탐색을 시작한다. 브라우저의 쿠키·리다이렉트·
DNS 정책이 적용되며 수집기 요청 예산 밖의 동작이다. 동일 주소 증거와 허용 origin·경로를 확인한
정상 페이지/JS 또는 정적 파일 참조에 제공한다. 쿼리·마스킹 주소·호출 후보·별도 오류 문서는 제외한다.
열 때 noopener,noreferrer를 지정한다. 미방문 파일의 실제 존재나 GET의 무해성은 미확인이다.
함수·변수 분석은 받은 JS의 구문과 선언 범위만 읽고 이름과 위치를 저장한다. 같은 파일의 직접 호출도
실행 여부는 미확인이다. 원문과 변수 값은 보고서에 넣지 않는다.

HTML도 output 경계와 UUID 파일명 검사를 적용하고 임시 파일 후 원자적으로 교체한다.
입력 JSON은 변경하지 않는다. 보고서에 대상 이름·경로·구조는 남으며 완전한 익명화 자료가 아니다.
파일 참조는 URL과 확장자/HTML의 단서일 뿐 서버 내부 파일 경로나 실제 존재를 보장하지 않는다.
